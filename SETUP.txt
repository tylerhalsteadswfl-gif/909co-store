909CO WEBSITE + OWNER ADMIN SETUP

WHAT THIS VERSION ADDS
- 909 TEE — PINK — $23.00
- 909 TEE — WHITE — $21.00
- Real product photos for the two new tees (front photos in the shop)
- Cart tracking across visitors
- Website visitor tracking
- Owner-only admin login
- Admin dashboard: unique visitors, people with items in active carts, items in active carts, and product/cart details

IMPORTANT
GitHub Pages is static hosting, so it cannot securely store the owner password or collect shared visitor/cart data by itself. This package uses Supabase as the small backend. Do not put a service_role key in config.js.

ONE-TIME SUPABASE SETUP
1. Create a Supabase project.
2. In Supabase, open SQL Editor and run this whole block:

create extension if not exists pgcrypto;
create table if not exists public.site_visits (
  id uuid primary key default gen_random_uuid(),
  session_id text not null,
  created_at timestamptz not null default now()
);
create index if not exists site_visits_session_idx on public.site_visits(session_id);

create table if not exists public.cart_sessions (
  session_id text primary key,
  cart jsonb not null default '[]'::jsonb,
  updated_at timestamptz not null default now()
);

alter table public.site_visits enable row level security;
alter table public.cart_sessions enable row level security;

create policy "public can record visits" on public.site_visits
for insert to anon, authenticated with check (true);

create policy "public can create carts" on public.cart_sessions
for insert to anon, authenticated with check (true);

create policy "public can update own cart row" on public.cart_sessions
for update to anon, authenticated using (true) with check (true);

create policy "admins can read visits" on public.site_visits
for select to authenticated
using ((auth.jwt() -> 'app_metadata' ->> 'role') = 'admin');

create policy "admins can read carts" on public.cart_sessions
for select to authenticated
using ((auth.jwt() -> 'app_metadata' ->> 'role') = 'admin');

3. Create ONE owner email/password account in Supabase Authentication. Do not enable public signup for this admin account.
4. In Supabase Authentication/User Management, set that owner's app_metadata role to: admin
   app_metadata JSON: {"role":"admin"}
5. In Supabase Project Settings -> API, copy the Project URL and anon/public key into config.js:
   window.SUPABASE_URL = '...';
   window.SUPABASE_ANON_KEY = '...';
6. Upload ALL files/folders in this package to the ROOT of the same GitHub Pages repository that currently hosts 909co.store.
7. Your owner dashboard will be at:
   https://909co.store/admin.html

NOTES
- Visitor counts are unique browser sessions, not guaranteed human beings. Clearing browser storage or switching devices creates a new session.
- "People with items in cart" is based on carts updated in the last 30 minutes.
- The admin page is not linked to ordinary visitors unless an owner is already logged into Supabase. Authentication/RLS is what protects the data; hiding a link alone is not security.
